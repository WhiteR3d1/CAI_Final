# บัญชีและ Google Sheets — 23 ตุลาคม 2026

## ข้อสรุปล่าสุดจากผู้ใช้
ไม่ใช้ Firebase และเอา Google login ออก ใช้เฉพาะ username/password ให้ตั้งค่าชีตและการสมัครใน Code.gs

## การออกแบบ
BB_CONFIG ต้น Code.gs กำหนด SHEET_ID และ ALLOW_REGISTRATION ส่วนค่าลับไม่ฝังในซอร์ส: setupBootBloom สร้าง BB_SESSION_SECRET_V2 ใน Script Properties อัตโนมัติและคงค่าเมื่อเรียกซ้ำ ไม่อ่าน SESSION_SECRET เดิม

คง schema ชีตเดิมเพื่อไม่ทำข้อมูลหาย ใช้ bcrypt cost 12, session 8 ชั่วโมง, ตรวจเจ้าของจาก session, LockService + revision + request ID, เก็บสรุปและ JSON แบ่งเซลล์ในแถวเดียว หน้าเว็บโหลดก่อนเปิดเกม แยกร่างตาม UID และหยุดเมื่อ conflict

Google frontend library, ปุ่ม และ backend OAuth ถูกนำออก ไม่มีการรวมบัญชี/ย้ายเซฟ Google เดิมอัตโนมัติ

คะแนนยังคำนวณ frontend ไม่ใช่ระบบสอบกันแก้คะแนน ทดสอบในเครื่องได้ แต่การเชื่อมชีตจริงรอเจ้าของติดตั้งและ deploy

## หน้าอาจารย์ — 1 พฤศจิกายน 2026

ผู้ใช้ขอส่วนของอาจารย์สำหรับดูหน้าร้านของนักเรียนแต่ละคน และกระดานแสดงการตกแต่งร้าน เลือกให้ **อาจารย์เห็นคนเดียว** (นักเรียนยังโชว์ร้านของตัวเองได้เหมือนเดิม) กำหนดบัญชีอาจารย์ด้วย `BB_CONFIG.TEACHERS` ใน Code.gs เพื่อไม่ต้องแก้คอลัมน์ในชีตและไม่ต้อง Run setupBootBloom ซ้ำ

API เพิ่ม 3 action ที่ตรวจสิทธิ์อาจารย์ทุกครั้งฝั่ง backend (ไม่เชื่อ flag จากเบราว์เซอร์) และอ่านอย่างเดียว:

- `roster` — รายชื่อนักเรียนพร้อมสรุปจากคอลัมน์ของ BB_Saves (เหรียญ/ดาว/งานที่ส่ง/เวลาอัปเดต) ไม่อ่าน JSON จึงเร็ว และไม่รวมบัญชีอาจารย์
- `shops` — การตกแต่งของนักเรียนครั้งละไม่เกิน 12 คน หน้าเว็บทยอยโหลดทีละ 8 คน
- `student` — เซฟเต็มของนักเรียนหนึ่งคนสำหรับหน้ารายละเอียดและคะแนนรายงาน

ไม่มี action ใดเขียนเซฟของนักเรียน ไม่ส่ง passwordHash หรือข้อมูล session ออกจาก backend และมี rate limit ของอาจารย์ 300 ครั้ง/ชั่วโมง

## บทบาทและผู้ดูแล — 1 พฤศจิกายน 2026

ผู้ใช้ขอให้ "ปรับบทบาทให้บัญชีที่สมัครได้" จึงย้ายการกำหนดบทบาทจาก Code.gs มาเก็บในชีต โดยเลือกให้ `role` เป็น**คอลัมน์ที่ 11 แบบเสริม**ของ BB_Accounts ไม่แตะ 10 คอลัมน์เดิมที่ `bbTable_` ตรวจ ชีตที่ยังไม่ผ่าน setupBootBloom รอบใหม่จึงใช้งานได้เหมือนเดิมทุกอย่าง (ถอยไปใช้รายชื่อใน Code.gs) ไม่มีจังหวะที่ระบบล่มระหว่าง deploy

บทบาท: `student` (ค่าเริ่มต้นของทุกบัญชีที่สมัคร), `teacher` (หน้าอาจารย์ อ่านอย่างเดียว), `admin` (หน้าอาจารย์ + `accounts`/`setRole`/`setDisabled`)

ลำดับความสำคัญ: `BB_CONFIG.ADMINS` → คอลัมน์ `role` → `BB_CONFIG.TEACHERS` → `student` เลือกแบบนี้เพราะต้องมี root of trust ที่หน้าเว็บแก้ไม่ได้ ไม่เช่นนั้นผู้ดูแลคนสุดท้ายอาจถูกถอดจนไม่มีใครเข้าหน้าจัดการได้ ส่วน `TEACHERS` ลดบทบาทเหลือเป็นค่าเริ่มต้น เพื่อให้คำสั่งจากหน้าเว็บมีผลจริง

ข้อห้ามที่บังคับใน backend: แก้บัญชีตัวเองไม่ได้ (`SELF`) และแก้บัญชีใน `ADMINS` ไม่ได้ (`FIXED`) · การปิดบัญชีใช้คอลัมน์ `disabled` เดิมที่ `bbAuth_` ตรวจอยู่แล้ว session ที่ค้างอยู่จึงหยุดทำงานทันทีโดยไม่ต้องลบแถวใน BB_Sessions · ผู้ดูแลแก้ได้เฉพาะ `role` กับ `disabled` ไม่มี action ใดแตะเซฟหรือรหัสผ่านของนักเรียน
